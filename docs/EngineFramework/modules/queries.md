# Queries

Status: B01 Goal 4 review. Local module contract only.

Responsibility: typed gameplay query descriptions, provider registration/freeze, snapshot coordination, consistency/coverage/accuracy requirements, budgeting, deterministic provider dispatch and detached response ownership. Public contract: `gameplay_queries.h`.

Authoritative state: provider registry/freeze state and snapshot-coordinator epoch where configured. Query responses are caller-owned detached values. Diagnostics are observational and are not authoritative gameplay state.

Dependencies: Framework Foundation contracts and caller-supplied provider/snapshot interfaces. Providers are external ports from the module's perspective.

Lifecycle and identity: provider registration occurs before freeze. Duplicate provider/type registrations are rejected. Query/type mismatch, invalid requirements and exhausted budgets return explicit failure rather than partial response publication. Provider order is deterministic according to the registry contract.

Persistence boundary: the service does not own a durable gameplay-state snapshot. Snapshot coordination exposes an epoch/consistency boundary for providers; whole-engine persistence remains Goal 5.

Failure and atomicity: provider failures do not leave a partially published query response. Registration/freeze operations preserve pre-state on failed publication.

Limits and threading: budgets bound provider work. The service is synchronous/caller-serialized unless a supplied provider documents stronger behavior; it does not create worker threads.

Local invariants and tests: `queries_tests.cpp` covers registration/freeze, duplicate/type mismatch, requirements, budget exhaustion, snapshot epoch, deterministic ordering, provider failure and detached response lifetime.
