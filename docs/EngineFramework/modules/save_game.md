# SaveGame

Status: B07 Goal 4 review. Local module contract only.

Responsibility: owns in-memory save participant registration, capture/restore barrier coordination, image metadata/section validation, migration planning, restore staging and ordered commit. Goal 4 deliberately does not add file I/O, storage ownership or serializer infrastructure.

Authoritative state: participant/migration registries, registry freeze state and diagnostic transaction phase/counters. Participant gameplay state remains owned by each registered participant.

Dependencies: Framework Foundation and EngineBase Foundation only. External collaboration is explicit through `ISaveParticipant`, `ISaveBarrier`, `ISaveBarrierLease`, `ISaveMigration` and `IRestoreStage` contracts.

Registration and lifecycle: participant IDs are unique, required/optional dependencies are resolved deterministically, migrations are versioned, and registration is rejected after freeze. Capture and restore leases are acquired and released by scope even when participant code fails or throws.

Capture contract: capture builds a complete in-memory `SaveGameImage` with structural metadata, section hashes and participant metadata before publishing success. Participant failure or exception cannot return a partial image.

Restore contract: image structure, version compatibility, hashes and migration chains are validated first. Every participant is validated and staged before the first live `CommitRestore`, dependency order is deterministic, and `CommitRestore` is the no-fail publication phase. The B07 `restore.pre_commit` seam sits after complete staging and before the first live commit.

Failure and atomicity: validation, migration and staging failures leave every participant untouched and release the barrier. Allocation failure at the B07 pre-commit seam also leaves all participants unchanged and does not enter commit.

Threading contract: synchronous caller-serialized orchestration. Barriers are explicit external synchronization points; SaveGame creates no worker thread.

Local invariants and tests: `save_game_tests.cpp` covers duplicates, freeze, dependency order, required/optional participants, capture failure/exception, validation/staging failure, migrations, hash/version corruption, deterministic restore order, barrier cleanup and pre-commit allocation failure.
