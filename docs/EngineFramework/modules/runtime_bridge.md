# RuntimeBridge

Status: B01 Goal 4 review. Local module contract only.

Responsibility: the sole Framework-to-Runtime boundary for semantic object materialization, generation-aware binding maps, projection queues, physics/world/environment/navigation observations, retry/reconciliation and cleanup. Public contract: `runtime_bridge.h`; Runtime-backed implementation: `RuntimeBridge/src/runtime_bridge.cpp`.

Authoritative state: Framework-side binding/generation maps, queued accepted projection work, reconciliation records, imported Runtime handles and bridge-local monotonic counters. Runtime systems remain authoritative for Runtime objects/bodies/regions themselves.

Dependencies: Framework Foundation and neutral Runtime World, Physics, Environment and Navigation contracts. Backend/service interfaces are explicit external ports.

Identity and lifecycle: one active Runtime materialization corresponds to one semantic binding generation. Forward/reverse maps must agree. Stale generation observations cannot mutate a newer binding. Create/update/remove, dematerialization and reconciliation are retry-safe according to the queue contract. Duplicate delivery is idempotent or explicitly rejected.

Persistence boundary: bridge-local mappings/reconciliation data are local checkpoint candidates. Whole-engine restore/re-materialization order remains Goal 5.

Failure and atomicity: accepted external work is not reported as semantic success until local terminal publication is established. Backend failure does not falsely advance semantic success. Queue budgets/backpressure preserve accepted work.

Numeric boundary: Runtime observations must be finite and representable by semantic types. Visibility geometry computes deltas and norm in `double`, rejects a true distance outside `RaycastQuery::max_distance` representability, and only then narrows a normalized direction and distance. It never clamps an out-of-range ray because clamping can produce a false visibility result.

Limits and threading: local handle counters are exhaustion-checked; queues are bounded by explicit processing budgets/policies. The bridge is synchronous/caller-serialized and owns no hidden worker thread.

Local invariants and tests: `runtime_bridge_tests.cpp` covers binding/retry/stale-generation behavior, duplicate/projection handling, backend failures, reconciliation and visibility geometry including `FLT_MAX`, opposite-sign large coordinates and near-zero distance.
